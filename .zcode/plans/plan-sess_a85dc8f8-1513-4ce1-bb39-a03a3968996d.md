# M7.8 全链路缺陷清偿计划（P1+P2+P3，6 个提交）

范围：审计报告全部条目，**`/init` 覆盖除外**（用户确认保持直接覆盖，不改）。每个提交独立过 `pnpm verify` + `pnpm lint`。预估新增 ~20 个测试用例。

## 提交 1 — fix(cli): 会话态访问器化（P1-1）

`/new`/会话切换后 seed 片段、审批审计、`todo/write`+`code-dispatch` emit、溢出 cacheDir 落旧会话的根治。方案：**消除按值捕获，改访问器**（不做 runner 全量改名，控制爆炸半径）：
- `session-runtime.ts`：`seedContextFragment` 签名改 `(session, messages) => Promise<void>`（读参数，不读闭包）；返回接口 docstring 注明"交互 runner 重绑后不得再读 `rt.session`/`rt.messages`"；用户级 skills 目录 `os.homedir()/.nova` 改走 `novaHome()`（P3 顺手）。
- `runner-shared.ts`：`createApprovalService` 第三参改 `getSession: () => Session`；`agentRunBase` 的 `session` 改 `() => Session` 访问器（cacheDir 与 emit 均经 accessor）。
- `repl.ts`/`tui-mode.ts`：传 `() => session`/`() => messages`；`/new` 与 `switchToSession` 重绑后调 `seedContextFragment(session, messages)`。
- 新增 `packages/cli/test/session-runtime.test.ts`：/new 往返（新 Session + seed → 片段落新文件、旧文件无孤儿）；approval 审计 accessor 落当前会话。

## 提交 2 — fix(plugins): 审批门与容器硬化（P1-2、P1-3、P2-9 + P3 三项）

- `permission.ts`：
  - `rememberKey`：`/[&;|\n\r]/` 或含 `$(`、反引号 → 整条规范化命令记忆（堵多行命令绕过 always 前缀 + 命令替换注入）。
  - `decide()` ask 路径**串行队列**（`askChain` promise 链）：并发 decide 时 asker 逐个派发，修复 PTC 并发子调用覆盖 TUI 弹窗导致 run_code 挂死；verdict 短路（记忆/自动放行）不入链。
- `host.ts`：`permissionFor` 抛错回落 `'execute'`（fail-closed），不再回落静态 `read`；`beforeToolCall` rewrite 信任缝在 host.ts + `agent.ts` preflight 处补注释（rewrite 参数不过审批门，当前无内置 rewrite）。
- `fs.ts`：`atomicWrite` rename 前 `chmod` tmp 为原文件 mode（保 exec bit；Windows 无害）。
- `ptc/json.ts`+`worker.ts`：`__proto__` own key 改 `Object.defineProperty` 写入，不再静默丢键/污染原型。
- 测试：permission.test.ts 扩展（多行绕过、`$()`、两并发 decide 的 asker 派发次序与互不悬挂）；json snapshot `__proto__` 用例。

## 提交 3 — fix(core)+fix(cli): 运行健壮性（P2-5、P2-6、P2-7 + 相关 P3）

- `core/agent.ts`：
  - runAgent 主体包 `try/finally`：生成器被弃用（runner 事件处理抛错致 for-await 提前 return）时——①未消费的 job 通知 `requeue`；②为"已 push 的 assistant.toolCalls 中尚无结果"的 callId 合成 `[not executed: the turn ended before this call ran]` 结果 push 进 surface（供 runner 持久化）。
  - `parseArgs` 改 `{ args, ok }`：malformed JSON 的工具调用**不再静默按 `{}` 执行**，直接产出"arguments were not valid JSON"错误结果让模型重发。
- `runner-shared.ts`：新增 `persistMissingToolResults(session, messages)`——扫尾部缺失结果的 toolCallId，以与 core 相同文案合成结果，push 进 surface 并 `session.append`（保住"model-visible means logged"）。三个 runner 的 turn 错误 catch 各接一行。
- `exec.ts`：装 SIGINT handler → abort 本次 runAgent（调用点补 `signal`），finally 的 `jobs.dispose()` 得以执行（后台 shell 不再孤儿）；`--json` 模式错误写 `{"type":"run_error",...}`、压缩 warn 写 `{"type":"notice",...}` 行（AGENTS.md §同步 schema）；`statusLine` 传真实耗时。
- `tui-mode.ts`：`rebuildHost()` 末尾重置四个 usage 锚点（工具集变更使锚点 schema 假设失效，P2-7）；`switchToSession` 打印 `loaded.warnings`。
- `repl.ts`：`/model` 选择提示与 `/compact` 等待期 Ctrl+C 走 `LineSource.cancelPending()`（复用 M6.9 审批等待模式）；compact 链路接 `signal`（现有参数从未被传入）。
- 测试：`persistMissingToolResults` 往返、parseArgs malformed 结果、anchors 重置（rebuildHost 后 preflight 用全量估算路径）。

## 风险与验证

- **config strict** 对带未知键的既有配置是行为变更（0.x 可接受，报错点名键名）。
- **exec SIGINT** 把 Ctrl+C 从硬杀改为优雅中止（预期改进；后台 job 走 dispose）。
- **POSIX detached 进程组**只在 POSIX 生效，Windows 路径不变；本机为 Windows，POSIX 行为靠代码审查 + 现有测试兜底。
- **ask 串行化**语义与原生并行审批一致（本就逐个串行），只是结构性保证。
- 每提交 `pnpm verify` + `pnpm lint` 全绿后提交；最后统一 `git push` 由你确认。
