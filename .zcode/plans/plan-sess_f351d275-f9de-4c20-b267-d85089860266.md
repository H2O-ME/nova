## jobs 完成通知(钩子注入,替代轮询)— 实现方案

### 背景
后台 bash job 跑完后,模型目前只能反复调 `jobs output` 轮询,每轮都烧 token。目标:job 自然结束时(completed/failed),在下一次 LLM 请求里自动注入一行"bash-N 已完成"通知,模型收到即读一次输出,不再空转轮询。

### 关键机制(已探明)
- `runAgent`(core/src/agent.ts:111-118)每轮先组装 `ChatRequest { messages, systemPrompt, tools, signal }`,再走 `beforeLLMCall` 钩子,然后 `provider.stream(request)`。`request.messages` 与 `opts.messages`(append-only 日志)**同一数组引用**——所以注入要**克隆数组** `[...opts.messages, notice]`,既上得了请求、又不污染日志,不破坏 `surfaceDivergence` 审计不变量(它只比对 live 日志 vs session 投影)。
- `JobRegistry`(core/src/jobs.ts:71-82)的 `done` watcher 是唯一识别终态的地方,目前只改状态、不通知任何人;注释明言"registry owns lifecycle + notification contract"。bash 的 killed 只来自显式 stop/dispose,模型自己停的不用再通知。

### 改动

**1. core/src/jobs.ts — 终态通知队列**
- 新增导出类型 `JobNotice = { id; kind; label; status: 'completed' | 'failed'; detail? }`。
- Registry 加 `private pendingNotices: JobNotice[]`;在 `start()` 的 done watcher 里,当非 stopping 且终态为 `completed`/`failed` 时 push 一条 notice(`killed` 跳过——那是显式 stop/dispose 的结果,模型已知或会话已结束)。
- 新增公开方法 `drainFinished(): JobNotice[]`:返回并清空队列(消费一次 = 通知一次,天然去重)。
- 新增纯函数 `formatJobNotices(notices): string`(放 jobs.ts 便于单测):每 job 一行,如 `- bash-1 [completed] <label 截断~80 字符> (exit code: 0)`,尾部加一句"用 jobs 工具 (action=output, id=…) 读取输出"。

**2. core/src/agent.ts — 请求注入(在钩子前)**
在 `agent.ts:111-117` 组装 request 之后、`beforeLLMCall` 之前插入:
```ts
const finished = opts.jobs?.drainFinished() ?? [];
if (finished.length > 0) {
  const msg: UserMessage = { id: newId('msg'), ts: Date.now(), role: 'user', content: formatJobNotices(finished) };
  request = { ...request, messages: [...opts.messages, msg] };  // 克隆,不落日志
}
```
- 每轮请求都会查一次,exec 单 runAgent 的长跑、TUI 下条 prompt 的首个请求都覆盖(空闲期完成的 job 在用户下一条消息时送达——正是 dsh inbox 语义)。
- 克隆数组在后续钩子里安全:exec 的 auto-compact `splice` 只改这份克隆;PTC 的 `{...req}` 展开会保留 messages。

**3. 行为塑造文案(模型侧,教它别空转轮询)**
- `packages/plugins/src/builtin/bash.ts:327`:后台 job 启动返回文案改为"完成时会自动收到通知;收到通知后 jobs output 读一次;需要提前终止用 action=stop"。
- `packages/plugins/src/builtin/jobs.ts` 工具 description 补一句"job 完成会自动注入通知,无需反复轮询"。两处无现成测试断言(已确认)。

### 不做的事
- 不在 cli 三个 runner 加任何代码(零接线)。
- 不在通知里带输出正文(保持上下文精简,输出仍在 jobs output 游标后)。
- 不做"空闲即自动打断/触发新轮"的主动通知——只在下次请求时送达。
