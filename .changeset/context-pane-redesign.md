「上下文」视图按 dsh-context 的水准重做（对齐参照的几何与词汇，不引第三方代码）：

- **统计条**（新）：轮次 / 请求 / 工具调用 / **缓存命中**——命中率取最新一条报告过 usage 的请求，与聊天用量 pill 共用 `cacheHitText`。
- **当前上下文**：大号读数 + 已用百分比；分段条 12px→**16px**，段间 2px 缝，未占满的窗口画成**斜纹剩余区**；图例带 token 数与**占已用**百分比；条与图例**悬停联动**（共享一个 hover 键），气泡锚在段自己的几何中心（CSS clamp 管边界）。
- **上下文趋势**：从「一根细柱」变成**真图表**——每请求一根 14px 堆叠柱（按类别自下而上）、左侧 5 档轴刻度（1/¾/½/¼/0，`formatTokens`）+ 虚线网格 + 实线零基线；悬停出气泡（时间 · 约 tokens），点击**钉住**；图表下方**明细行**给出该请求的时间、估算、输入/输出/缓存命中与构成图例；打开时滚动锚定到最新一端。
- **窗口元素**（新卡）：构成条背后的**开箱**——窗口里的每个计价单元（工具 schema、注入片段、消息）。成形为**每个类别一张可折叠卡**（参照浏览器的骨架）：卡头给该类别的项数/token/占比，卡内行按占用降序、带预览文本。一张平铺表会被十几个 ~1% 的工具 schema 淹没，真正撑起窗口的几条（注入文档、系统提示）反而看不见——分组让「谁在占地方」一眼可读。
- **上下文事件**：按 kind 的筛选 chips（压缩/工作区/目标，含计数与字形）+ 每种 kind 的着色药丸（`currentColor` 上色，一个 tone 类同时管字形/筛选/药丸）。
- **文件活动**：每个路径按用途**逐枚徽章**（读取/写入/搜索，各自计数）替代原来「按支配规则选一句话」的摘要——后者会静默藏掉一条路径的另一半事实；写入行数增减改画成 `+增/−删`。

实现上把面板的纯模型按问题拆成四份（`context-model` 构成/统计、`trend-model` 趋势、`element-model` 元素、`activity-model` 事件与文件），每份都有直测；渲染测试补一条 SSR 直测。

**修一处随之暴露的滚动缺陷（用户报告「不能上下滚动，卡在这了」）**：上下文 / 轨迹两个面板在**共享 rollport**（会话的 `[data-conversation-scroll]`）之外又开了一层自己的 `overflow:auto` + `overscroll-behavior: contain`，而那层的内容永远装得下（面板跟着内容长高）——**没有滚动范围的内层照样吞掉滚轮**（contain 不把带不动的滚动链给父级），于是整页滚不动。现在两个面板都不再自开滚动条，滚动归共享端口（与转录同一套 `scrollportOf`）；上下文面板挂载时把端口回锚到自己的顶部（转录离开时它停在转录底部）。真机 A/B：修复前滚轮 → scrollTop 不动（0）；修复后 → 300；把旧 CSS 注回面板 → 又回到 0。

**刻意未移植**（数据面不在本仓）：费用/计价、跨会话仪表盘与热力图、计时 spans、智能体网络图、轮次条（会话日志没有 turn/step 坐标）、自动压缩预留带（内核按 `autoCompactTokenLimit` 绝对阈值压缩，窗口比例不是它的事实）。悬停气泡与明细行不再重复读数：气泡只报身份+总量，用法读数归明细行。
