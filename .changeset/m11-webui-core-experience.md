**WebUI 核心体验：内核量测 + 分页基线 + 详情/统计/活动面**。

- **`RunMeter` 与 `run_stats` 事件（core 新公共面）**：内核在 `consume()` 这个唯一汇聚点上量一个轮次的耗时、首 token 时间、请求与工具调用各自的用时、请求数/工具调用数/重试数，以及逐请求累加的输入/输出/缓存 token，跑完以 `run_stats` 发出。它是**观测事件**：不落会话日志、不进模型可见面（与 `reasoning_delta` 同族）。`run_stats` **在 `done`/`run_failed` 之前**发出——终结符是消费者等的最后一帧，统计跟在它后面就会被只等终结符的消费者漏掉。
- **回放基线分页（`load_earlier` 帧）**：`ready` 不再整包发历史——只发最后 40 块并附 `historyTotal`；客户端用 `load_earlier { have }` 逐批取更早的块（`history_earlier` 应答）。服务端持一份冻结的投影快照，游标按它计数，实时事件只追加在客户端的活区。"已经全部持有"回空批而不是报错。会话列表/会话切换语义不变。
- **工具块携带结果原文与时间戳**：回放块新增 `output`（结果文本，详情面板的内容）与 `ts`（转录时钟）——否则重新 attach 之后历史里的工具行点不开详情。
- **surface 新增**：①工具行是按钮，点击在右侧打开**详情侧板**（完整参数、结果原文、时间）；②**每轮元数据行**（`9月20日 23:46 · 用时 5.7s · 首 token 1.6s · 23 tok/s`）与**底部会话统计条**（轮数/步数 · LLM 时间/工具时间 · 首 token 平均/吞吐 · 缓存命中 · 输入输出 tokens），全部由 `run_stats` 求和，表面自己不算任何数；统计条在会话重开时清零；③**后台 job 活动行**（转录内一行一处、原地改写，直到 job 结束）；④**重试/空补全行**——`llm_retry` 与 `empty_completion` 此前被浏览器端 reducer 静默丢弃，现在落成转录里的告警行；⑤"加载更早"按钮与未加载计数。
- 缓存命中率在 provider 未上报缓存时**不显示**（0 命中不等于"完全不命中"，与内核的 miss 审计同一道护栏）。
- 验收：`pnpm smoke:web` 扩到 23 项并全绿（新增 bundle 标记、`ready.historyTotal`、工具结果原文长度、真轮的 `run_stats`——实测 `requests=2 first=2897ms dur=6036ms in=25111 out=166`）；浏览器逐项点过工具详情侧板与分页回补。
