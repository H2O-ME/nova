右栏**整体重写**（前端与后端一起，不是打补丁）——操作者报障五条：git 状态卡在「正在读取 git 状态…」、视觉没对齐 dsh、文件页要求重新选一遍工作区、预览必须点开才有、终端与任务面板「全是一坨」。旧实现整体删除（`FilesWindow` / `FilesPanel` / `TreePanel` / `TreeMenu` / `ChangesPanel` / `GitLens` / `EditorPanel` / `TerminalPanel` / `TasksPanel` / `terminal-model` / `tree-menu-model` / `tree-rows` / `session-files` / `web/src/terminal-frames.ts`）。

- **标签条 + 开始页（不是固定四页签）**：`rightbar/tabs.ts` 定义的是**可开的四页**（变更 / 文件 / 任务 / 终端），strip 画的是**已开的页**——一页一枚标签（图标 + 标题 + ×，160px 上限走省略号、右邻 hairline、活动标签用填充色而非下划线），右侧一枚 `+` 菜单只列未打开的页，最右是面板自己的全屏/关闭钮。标签全关时正文是**开始页**（`StartView.tsx`：56px 罗盘水印 + 四张 380px 入口胶囊），照抄参照 `ui-sidebar-right/tabs/guide/GuideBody` 的几何。树停靠在文件页内，**点文件就在树旁边打开**（参照件自己的形状，`builtins/tabs.ts` 的编辑器页就是文件窗），「找文件」与「读文件」不再分居两个页签。记住的旧 `editor` 页偏好归默认页。
- **终端是真 PTY**：宿主经 `node-pty`（**惰性 import**，原生插件缺席时答 `unavailable` 而不崩服务器）spawn `sessionEnv().shell` 的交互 shell，stdin 是真键盘、stdout 是真 ANSI 字节流——**vim / top / Ctrl-C 全部真实工作**，`cd` 因进程常驻而保留。浏览器侧用 `@xterm/xterm` + addon-fit 画屏（**动态 import** 进懒加载 chunk，SSR 测试车道零 DOM 不受累）。协议四帧：`term_open {cols, rows}`（确保 pty 并以应答重放保留的 scrollback，`reset:true` 让重挂/重载整屏重建）、`term_input {data}`（控制字符是内容，只限长）、`term_resize`（SIGWINCH）、`term_kill`（杀树并广播 reset）。**退出的 pty 绝不静默替换**——scrollback 是「为什么死」的最后读数，重启是显式 kill+open。上限 `MAX_TERM_INPUT_CHARS = 16384` / `MAX_TERM_COLS = 500` / `MAX_TERM_ROWS = 500`。（此前一版用管道 + 哨兵标记模拟 shell，`shell_run` / `shell_read` / `shell_stop` 三帧随本次重做删除，从未发行。）
- **git 状态走缓存**：`GitStatusCache`（TTL 2000ms + 并发单飞 + 写动作 `invalidate`）——git 是子进程，每次开页冷启一次正是「正在读取 git 状态…」的来源。`list_jobs` 拆进 `job-frames.ts`（行里只带状态/进度，不带输出）。
- **两条归约纪律修复（各有 killing test）**：①**答案不能开对话框**——文件页自己问的 `list_directory` 答案曾被工作区选择器当成自己的答案，于是每次打开面板都弹「选择工作区文件夹」；现在 `directory` 槽位只在手势（`directory_open`）之后存在。②**请求出发处拥有「打开」**——`read_entry` 一发出，`sent` 归约就把文档放进编辑器（`loading`），`entry` / `entry_error` 只结算已经存在的文档；此前 `editor_open` 动作全仓没有派发者，点树里的文件只发帧、预览永远空着。
- **前端**：`rightbar/kit.tsx` 原语（28px IconButton / 22px chip / 28px 段头 / 文本 Notice / StateDot 环）之上，一页一文件；纯模型（`change-tree` / `git-diff-rows` / `editor-model` / `terminal-model` / `tree-selection` / `git-marks`）全部 DOM-free 直测。记名偏离见 `docs/dsh-parity-inventory.md`（docking kit 只搬外观没搬机器：无拖拽换序/中键关闭/右键菜单/多 pane；开始页胶囊不挂快捷键 chip；无 diff 拖拽手柄；任务页不给输出窗；每会话单一终端）。

**追加（同日第二轮，操作者再报两条）**：①`unknown frame type: git_status` / `shell_read` 的报错是**界面比正在运行的 nova 进程新**（旧进程照常服务新 bundle）——`host-messages.ts` 的 `hostErrorText` 把宿主的裸帧名转写成「请重启 nova 进程」，其余错误保持原话。②工作区没有 git 时的变更页不再是一句死提示，而是 VSCode 源代码管理同款空态卡（`GitSetup.tsx`：源代码管理 + 打开文件夹 / 克隆仓库）：打开文件夹复用原生对话框选择器；克隆走**新客户端帧 `git_clone`**（core 新模块 `git-clone.ts` 的 `gitClone` / `repoNameOf`，argv-only + `--` 分隔 + 安全目录名门 + 10 分钟墙钟），与 `set_workspace` / `delete_session` 同族（session-target：改变「打开的是什么」，答复是重述的 `ready`——克隆落成当前工作区的兄弟目录并直接打开），失败走普通 error 帧、工作区原地不动；进行中态 `clonePending` 随请求置位、由 ready 或 error 结算。
